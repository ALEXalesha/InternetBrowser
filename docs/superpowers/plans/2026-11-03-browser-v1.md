# InternetBrowser 0.1.0 - план этапов

Дата: 03.11.2026. План - Claude, по описанию замысла `docs/superpowers/specs/2026-10-17-browser-design.md`
(одобрено Алексеем 24.10). Ветка `claude/browser-v1`, в конце - черновик PR в main.

## Устройство

```
src/core/   чистые модули без Electron (покрытие ветвей >= 90 %)
  omnibox.js    строка адреса: адрес или поиск, подсказки из истории и закладок
  tlds.js       список доменов верхнего уровня для разбора
  search.js     поисковики и адрес запроса
  sites.js      «сайт» по адресу (для выключателя блокировки и счётчика)
  blocker.js    решение «блокировать или нет» поверх движка фильтров + счётчики
  filters.js    откуда и когда брать списки (EasyList, EasyPrivacy), запасной список
  store.js      SQLite (встроенный node:sqlite): история, закладки, загрузки, настройки, сайты
  chrome.js     импорт из Chrome: профили, файл Bookmarks (JSON), копия History (SQLite)
  downloads.js  имена файлов в «Загрузках», состояния загрузки
  tabs.js       модель вкладок: порядок, активная, закрытые
  keys.js       горячие клавиши
  i18n.js       строки RU/EN
  themes.js     темы Paint: Стеклянная, Строгая, Светлая, Ночная, Тёплая
  ua.js         строка браузера без «Electron» (иначе часть сайтов ломается)
  netpolicy.js  куда самому браузеру можно ходить («ничего не уходит наружу»)
src/main/   главный процесс Electron: окно, вкладки WebContentsView, протокол ib://, IPC
src/ui/     полоса вкладок и адресная строка (свой интерфейс, Liquid Glass)
src/pages/  внутренние страницы ib://newtab, history, bookmarks, downloads, settings
tests/unit  законы node:test на случайных входах с зерном (IB_SEED)
tests/app   Playwright для Electron, локальный сервер со страницами и «рекламой»
tools/      mutate.js, fetch-lists.js, screenshots.js, make-icon.js
```

Решения:
- Хранение - SQLite через встроенный `node:sqlite` (есть и в Node 24, и в Electron 44): без нативных модулей и сборки.
- Блокировка - `@ghostery/adblocker` (движок, MPL-2.0) напрямую, без обёртки для Electron: так выключатель на сайте
  и счётчик по вкладке - свои и проверяются законами. Сеть режется в `webRequest`, косметика (скрытие элементов) -
  `insertCSS`. Главная страница (документ вкладки) не режется никогда - обычные сайты открываются.
- Списки EasyList и EasyPrivacy не лежат в git (3,5 МБ, своя лицензия): `npm run lists` кладёт их в `filters/` для
  сборки, браузер обновляет копию в папке профиля раз в неделю (официальный адрес, запасной - зеркало на GitHub).
  Без списков работает маленький встроенный запасной.
- Всплывающие окна (подсказки адреса, меню блокировки, главное меню) рисует тот же вид интерфейса: на время он
  растягивается на всё окно с прозрачным фоном поверх страницы.
- Ничего наружу: значки сайтов берутся через сеанс вкладки и хранятся у себя (data:), у интерфейса и внутренних
  страниц CSP без сети, проверка орфографии не качает словари, подсказки поиска - только из своей истории.
  Закон в окне: браузер запускается через записывающий прокси, наружу не должно уйти ни одного запроса.
- Строка браузера без «Electron/..» и имени приложения: часть сайтов иначе считает его не настоящим браузером.

## Этапы (по 1-3 часа)

1. **Каркас.** package.json, .gitignore, c8 с порогами, помощник законов (зерно, `forAll`), CI (ubuntu, node 24, xvfb).
2. **Адресная строка.** omnibox + tlds + search. Законы: любой ввод даёт допустимый адрес http(s)/ib/about/file;
   ввод с пробелом без схемы - поиск; запрос раскодируется обратно в ввод; домены и IP - адрес с тем же хостом;
   разбор идемпотентен; `javascript:` и прочие опасные схемы - только поиск.
3. **Хранилище.** store: история (визиты, поиск, удаление), закладки (папки, порядок), загрузки, настройки, сайты.
   Законы: туда-обратно после перезапуска, поиск находит всё подходящее и только его, удаление не задевает чужое.
4. **Блокировщик.** blocker + filters + sites. Законы на тестовом списке и случайных запросах: блокирует то, что должен;
   выключенный сайт не трогается вовсе; документ вкладки не режется; счётчик = числу блокировок; расписание недели.
5. **Импорт Chrome.** Поиск профилей, Bookmarks JSON, копия History. Законы на поддельном профиле со случайными
   данными: всё перенесено, повторный импорт не плодит дубли, файлы профиля не изменены (только чтение копии),
   время Chrome (с 1601 года) переводится верно.
6. **Загрузки и мелочи ядра.** downloads, tabs, keys, ua, i18n, themes, netpolicy с законами.
7. **Оболочка Electron.** Окно, вкладки WebContentsView, ib://, preload с проверкой отправителя, интерфейс:
   вкладки, кнопки, адресная строка с подсказками, щит со счётчиком и выключателем, темы и языки.
8. **Внутренние страницы.** Новая вкладка (часы, быстрые ссылки), история с поиском, закладки, загрузки, настройки
   (тема, язык, поисковик, блокировка, обновление списков, импорт из Chrome кнопкой).
9. **Законы окна.** Playwright: невидимое окно без фокуса; локальный сервер со страницей и «рекламой» - блокировка,
   счётчик, выключатель; «ничего не уходит наружу» (записывающий прокси); 20 запусков без роста памяти; узкое окно;
   все темы - читаемость (контраст) и отсутствие наложений; загрузка в папку; импорт из поддельного профиля кнопкой.
10. **Мутанты.** tools/mutate.js: каждый закон ловит свою поломку.
11. **Оформление.** README (en, ru), снимки окна, CHANGELOG (0.1.0 не выпущено), electron-builder (NSIS + portable),
    значок. Черновик PR.

Правило: найденный недочёт - сначала закон, который его ловит, потом исправление.

## Ход работ (04.11.2026)

Все 11 этапов сделаны в ветке `claude/browser-v1`. Недочёты, найденные законами (сначала закон, потом
исправление):
1. Половинка эмодзи (одиночный суррогат) роняла кодирование поискового запроса.
2. Время Chrome (~1,3e16 мкс) больше безопасного целого JS - node:sqlite бросал RangeError при импорте.
3. «CON.tar.gz» считался обычным именем загрузки, а Windows такой файл не создаст.
4. Первые подресурсы новой страницы судились по старому адресу вкладки (Electron обновляет его позже) -
   на сайте с выключенной блокировкой реклама следующей страницы проходила.
5. Поиск на странице: в Electron findNext=true значит «новый поиск», было наоборот - счётчик молчал.
6. «Настройки», сразу затем «История» занимали одну и ту же новую вкладку.
7. Контраст: приглушённый текст в четырёх темах и белый текст на акцентных кнопках были ниже 4,5:1.

Мутанты вскрыли слабые законы (генератор не ставил пробел после пути, идемпотентность не видела ib://,
закон настроек не проверял типы, «страница ошибки» в законе списков не имела заголовка отдельной строкой) -
законы усилены; равносильные мутанты (защита продублирована) заменены настоящими поломками.
